# World Heritage Cards — مواصفات المنتج (MVP)

## نظرة عامة
- **الملخص**: منصة ويب تفاعلية تعرض المواقع التراثية العالمية عبر بطاقات رقمية قابلة للجمع، تبدأ بالتراث العراقي (حوالي 20 بطاقة)، مع دعم للتوسع إلى كل الحضارات دون إعادة تصميم.
- **الغرض**: تجربة تعليمية تجمع بين جاذبية البطاقات القابلة للجمع والمصداقية الأكاديمية للمتاحف الرقمية.
- **المستخدمون المستهدفون**: المهتمون بالتراث والتاريخ، الطلاب، الباحثون، والجمهور العام.

## الأهداف
- بناء تجربة بطاقات تفاعلية فاخرة (ميل 3D، قلب، انعكاسات ضوئية).
- عرض 12–20 موقعاً تراثياً عراقياً بمحتوى موثق.
- دعم اللغتين الإنجليزية والعربية مع اتجاهات LTR/RTL صحيحة.
- تصميم معماري قابل للتوسع: نماذج بيانات قوية، فصل منطقي، API مستقر.
- تجربة ضيف تعمل بدون تسجيل (مجموعة محلية عبر localStorage).

## غير أهداف (للنطاق الحالي)
- نظام مصادقة كامل و cloud sync.
- لوحة إدارة محمية بقاعدة بيانات (سيتم تمهيد البنية فقط).
- تطبيق موبايل أصلي (Expo/React Native) — فقط التهيئة المعمارية.
- محرر Three.js ثلاثي الأبعاد لكل بطاقة.

## المتطلبات الوظيفية
- **FR-1**: مكون بطاقة قابلة لإعادة الاستخدام يدعم ميل 3D، قلب، انعكاسات ضوئية، وحالات hover/focus/pressed/selected.
- **FR-2**: معرض بطاقات أفقي تفاعلي (carousel) مع سحب، تنقل بالأسهم، وتنقل بلوحة المفاتيح.
- **FR-3**: صفحة استكشاف (Explorer) بشبكة بطاقات متجاوبة، بحث بالاسم، فلاتر (دولة، حضارة، فترة، فئة، ندرة)، وفرز.
- **FR-4**: صفحة تفاصيل نصب لكل نصب مع URL قابل للمشاركة، صورة كبيرة، نظرة عامة، تواريخ، حضارة، معالم معمارية، أهمية، حالة الحفظ، معرض الصور، خط زمني، نصب ذات صلة.
- **FR-5**: صفحة "مجموعتي" تعرض البطاقات المجمعة والمفضلة مع التقدم ونسبة الإكمال، باستخدام localStorage.
- **FR-6**: رحلات تعليمية مرتبطة (Learning Journeys) أساسية.
- **FR-7**: دعم اللغتين الإنجليزية والعربية مع RTL/LTR.
- **FR-8**: نظام ندرة (Common/Rare/Epic/Legendary) مستقل عن الأهمية التاريخية.
- **FR-9**: تصنيف كل نصب حسب: دولة، منطقة، حضارة، فترة تاريخية، نوع النصب، الأهمية، تعيين اليونسكو عند التحقق.
- **FR-10**: تفريق واضح بين الحقائق الثابتة، التفسيرات العلمية، التقاليد التاريخية، والنقاشات غير المحسومة (خاصة حدائق بابل المعلقة).

## المتطلبات غير الوظيفية
- **NFR-1**: استجابة كاملة للهواتف واللوحات وأجهزة المكتب.
- **NFR-2**: دعم reduced-motion وإمكانية الوصول (keyboard nav، semantic HTML، تباين).
- **NFR-3**: تحميل الصور بشكل متدرج (lazy loading) ومنع layout shift.
- **NFR-4**: SEO-friendly لصفحات النصب.
- **NFR-5**: فصل واضح بين طبقات البيانات والأعمال والعرض.
- **NFR-6**: نموذج بيانات قابل للتوسع لدول وحضارات جديدة دون تغيير بنية التطبيق.

## القيود
- **التقنية**: Next.js + TypeScript + Tailwind CSS + Framer Motion + CSS 3D transforms.
- **البيانات**: ملفات محلية مُكتبة (TypeScript) للـ MVP، مع مهيأة لاحقة لـ Supabase/PostgreSQL.
- **الأعمال**: عدم اختلاق تواريخ أو مصادر أو تسميات اليونسكو. استخدام صور ذات تراخيص صالحة أو placeholders مُعرَّفة بوضوح.

## الافتراضات
- الصور الحقيقية قد لا تتوفر؛ سيُستخدم placeholders مُحددة بوضوح.
- لا يوجد backend في MVP؛ البيانات ثابتة في الكود.
- التخزين المحلي (localStorage) يكفي لمجموعة الضيف.

## معايير القبول

### AC-1: مكون البطاقة التفاعلي
- **Type**: `rule`
- **Given**: بطاقة مُعروضة
- **When**: يحرك المستخدم المؤشر فوقها
- **Then**: تميل البطاقة بزاوية 3D بناءً على موضع المؤشر، ويظهر انعكاس ضوئي متحرك، وتنقلب عند النقر لإظهار الوجه الخلفي
- **Pass Condition**: جميع الحالات الثلاث تعمل بشكل سلس مع دعم touch و reduced-motion
- **Evidence**: تشغيل التطبيق وفحص التفاعلات

### AC-2: معرض البطاقات (Carousel)
- **Type**: `rule`
- **Given**: صفحة بها معرض بطاقات
- **When**: يسحب المستخدم أو يستخدم الأسهم أو لوحة المفاتيح
- **Then**: تنتقل البطاقات بسلاسة مع تأثيرات عمق وقياس، ولا يُحدد بطاقة أثناء السحب
- **Pass Condition**: التنقل يعمل عبر جميع الوسائط بدون تسرب أحداث السحب للنقر
- **Evidence**: فحص يدوياً

### AC-3: استكشاف البطاقات مع الفلاتر
- **Type**: `rule`
- **Given**: صفحة الاستكشاف
- **When**: يبحث المستخدم أو يطبق فلاتر أو يفرز
- **Then**: تُحدث الشبكة ببطاقات تطابق المعايير الفعلية للحظة، مع حالة فارغة عند عدم وجود نتائج
- **Pass Condition**: البحث والفلاتر والفرز تعمل على بيانات حقيقية
- **Evidence**: فحص يدوياً

### AC-4: صفحة تفاصيل النصب
- **Type**: `rule`
- **Given**: بطاقة محددة
- **When**: ينقر المستخدم على "استكشاف"
- **Then**: يُنتقل إلى صفحة تفاصيل بعنوان URL مستقر يعرض كل الحقول المطلوبة
- **Pass Condition**: صفحة كاملة بكل الأقسام المطلوبة وURL قابل للمشاركة
- **Evidence**: فحص يدوياً

### AC-5: دعم اللغتين والاتجاه
- **Type**: `rule`
- **Given**: التطبيق
- **When**: يبدل المستخدم اللغة بين الإنجليزية والعربية
- **Then**: يتبدل الواجهة واتجاه التخطيط (LTR/RTL) والمحتوى الترجمي
- **Pass Condition**: كل النصوص مترجمة والتخطيط RTL صحيح للعربية
- **Evidence**: فحص يدوياً

### AC-6: مجموعة الضيف المحلية
- **Type**: `rule`
- **Given**: مستخدم ضيف
- **When**: يضيف بطاقة لمجموعته
- **Then**: تُحفظ في localStorage وتظهر في صفحة المجموعة مع نسبة الإكمال
- **Pass Condition**: البقاء بعد تحديث الصفحة
- **Evidence**: فحص يدوياً

### AC-7: المصداقية الأكاديمية لحدائق بابل
- **Type**: `rule`
- **Given**: صفحة حدائق بابل المعلقة
- **When**: يقرأ المستخدم المحتوى
- **Then**: يُوضح بشكل صريح أن وجودها وموقعها غير مؤكد أثرياً، مع عدم تقديمها كحقيقة مثبتة
- **Pass Condition**: نص يوضح عدم اليقين ويستخدم لغة شرطية
- **Evidence**: فحص المحتوى

### AC-8: جودة التصميم البصري
- **Type**: `rubric`
- **Dimension**: الهوية البصرية الفاخرة والمتسقة
- **Scale**: 1-5
- **Anchors**: 1 = تصميم عام ورديء; 3 = مقبول لكن غير مميز; 5 = تصميم سينمائي فاخر بهوية مميزة
- **Pass Threshold**: >= 4
- **Evidence**: فحص بصري

### AC-9: الاستجابة وإمكانية الوصول
- **Type**: `rubric`
- **Dimension**: تجربة متجاوبة يمكن الوصول إليها
- **Scale**: 1-5
- **Anchors**: 1 = متصدعة على الجوال; 3 = تعمل لكن مع مشاكل; 5 = سلسة على كل الأحجام مع دعم كامل للوصول
- **Pass Threshold**: >= 4
- **Evidence**: فحص بمتصفح وأدوات المطور

## أسئلة مفتوحة
- هل توجد صور مرخّصة متاحة أم سنعتمد على placeholders؟ (افتراض: placeholders مُعرَّفة)
